# Provider Adapter cho Embedding: OpenAI, Mistral, Jina, Ollama + Tùy chỉnh — kèm Batch API

## Phạm vi đã chốt với user
- **Chỉ tab Embedding** (LLM giữ nguyên `ThinkingChatOpenAI`; cấu trúc registry sẵn sàng mở rộng cho LLM sau).
- 5 provider: `openai`, `mistral`, `jina`, `ollama`, `custom` (OpenAI-compatible tùy chỉnh — giữ vì tokenrouter và đuôi dài market chỉ chạy được nhờ lớp generic).
- Tận dụng capability từng nhà: OpenAI `dimensions` (MRL), Jina `task` (query/passage) + `dimensions`, Mistral `output_dimension`; **Batch API cho OpenAI + Mistral + Jina**.
- **Chiều vector KHÔNG fix cứng**: mỗi model preset khai báo danh sách chiều hỗ trợ (từ docs) → đổ vào dropdown "Chiều vector" cho user chọn; vẫn giữ ô "Khác…" như hiện tại.
- **Batch là checkbox cấu hình per-integration** ("Dùng Batch API −50%"), chỉ hiển thị khi provider hỗ trợ. Worker đi batch khi provider hỗ trợ **và** integration được tích.
- Không expose `output_dtype`/`embedding_type` binary/int8 — pgvector chỉ nhận float32.

## 1. Registry mới: `src/core/providers/`

```
src/core/providers/
  __init__.py      # PROVIDER_REGISTRY, get_embedding_provider(id) — id lạ → raise ValueError (không fallback)
  base.py          # ProviderSpec, ModelPreset, EmbeddingConfig, EmbeddingAdapter protocol, BatchStatus types
  openai_compat.py # adapter nền (dùng cho "custom") — sync embed qua openai SDK
  openai.py        # + dimensions param (MRL) + Batch /v1/batches (openai SDK files+batches)
  mistral.py       # + output_dimension + Batch /v1/batch/jobs (httpx)
  jina.py          # + task retrieval.query/passage + dimensions + Batch /v1/batch/embeddings (httpx)
  ollama.py        # không cần key, không dimensions param, không batch
```

- `ProviderSpec`: id, display_name, default_base_url, requires_api_key, supports_batch, models: `list[ModelPreset(name, dimensions: list[int])]` (dimensions = các chiều user được chọn; max = chiều native).
- Sync client: **openai SDK trực tiếp** (`openai.OpenAI(base_url, api_key)`) thay vì wrapper `OpenAIEmbeddings` — kiểm soát đủ params qua `extra_body`, loại luôn workaround `check_embedding_ctx_length=False` (src/core/embedding.py:99). `EmbeddingIntegrationService.test_connection` (hiện tự dựng client thứ 2 tại embedding_integration_service.py:269) cũng route qua adapter.
- Params provider chỉ gửi khi model nằm trong preset tương ứng (model lạ → request OpenAI-compatible thuần → an toàn cho custom model).

## 2. Embedder + call sites

- `resolve_active_config()` → `EmbeddingConfig` dataclass (base_url, api_key, model, dimension, **provider**, **use_batch**); fingerprint cache thêm provider.
- `embed(texts, input_kind="passage")`, `embed_one(text, input_kind=...)` — Jina ánh xạ sang `task`; nhà khác bỏ qua.
- Call sites: `src/core/retrieval.py:66` → `input_kind="query"`; `src/ingestion/worker.py:337` → `"passage"` (nhánh sync).
- Validate chiều + L2 normalize giữ nguyên ở `Embedder.embed` (hợp đồng pgvector không đổi).

## 3. API validation + endpoint presets

- Route `src/api/routes/embedding_integrations.py`: `provider: Literal["openai","mistral","jina","ollama","custom"]` ở Create/Update (422 khi lạ); `use_batch: bool = False` mới ở Create/Update/response — **validate: `use_batch=true` nhưng provider không hỗ trợ batch → 422 tường minh**.
- **GET `/embedding-integrations/providers`** → danh sách spec (id, display_name, default_base_url, requires_api_key, supports_batch, models kèm dimensions list) — backend là nguồn sự thật, UI render từ đây.
- Test connection: thêm `provider` (sync test, không test batch).
- Row cũ giữ nguyên `provider="openai"`, `use_batch=0`; nếu base_url thực tế là nhà khác thì user sửa 1 lần trong UI (không auto-fix im lặng).

## 4. Schema migration

- `embedding_integrations`: thêm cột `use_batch INTEGER NOT NULL DEFAULT 0` — `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` chạy trong schema khởi động (schema.py là nguồn DDL duy nhất).
- `files`: thêm `batch_job_id TEXT NOT NULL DEFAULT ''`, `batch_meta TEXT NOT NULL DEFAULT ''` (JSON: provider/model/base_url/dimension để resume đúng integration đã submit).

## 5. Batch ingestion (worker)

- Protocol adapter: `submit_embedding_batch(items: list[(custom_id, text)]) -> job_id`; `get_batch_status(job_id) -> BatchStatus(state, completed, total)`; `fetch_batch_results(job_id) -> dict[custom_id, vector]`.
  - **OpenAI**: SDK `files.create(purpose="batch")` + JSONL `{custom_id, method:"POST", url:"/v1/embeddings", body:{model, input}}` + `batches.create(completion_window="24h")`; status + `request_counts` từ `batches.retrieve`; kết quả từ `output_file_id` → `files.content`, map theo `custom_id`.
  - **Mistral**: httpx — upload file JSONL purpose="batch" → `POST /v1/batch/jobs {input_files, model, endpoint:"/v1/embeddings"}` → poll `GET /v1/batch/jobs/{id}` → tải output.
  - **Jina**: httpx — `POST /v1/batch/embeddings {model, input:[...], task:"retrieval.passage"}` (≤10k) → 202 `{batch_id}` → poll `GET /v1/batch/{id}` → tải `/v1/batch/{id}/output`.
  - File vượt giới hạn batch của provider (50k OpenAI / 10k inline Jina) → fail tường minh với thông báo rõ (không fallback im lặng).
- `src/ingestion/worker.py`:
  - Bước embedding: provider hỗ trợ batch **và** integration `use_batch=1` → submit toàn bộ chunks (custom_id = chunk_id), set status **"batching"** + batch_job_id/batch_meta, notify, worker xử lý file kế tiếp. Còn lại (không batch hoặc ollama/custom) → giữ vòng lặp sync 16/batch như cũ.
  - Loop worker: `queue.get(timeout=2s)`; mỗi vòng poll các file "batching" theo batch_meta: job xong → fetch results → validate dim → L2 normalize → `insert_chunk` → `set_file_status("ready")`; job failed/expired → status failed với error rõ; đang chạy → cập nhật `chunks_done` từ request_counts (nếu API báo) + notify.
  - `fail_interrupted_ingests()`: **không** đánh failed file "batching" — resume poll từ batch_meta (job nằm ở provider nên resume là đúng); job mất/hết hạn → failed rõ ràng.
- Poll interval 30s (const). `progress()` thêm "batching" vào tập processing.

## 6. UI

- **IntegrationPanel tab Embedding**:
  - Dropdown "Nhà cung cấp" (5 options, tái dùng portal pattern của dimension dropdown — IntegrationPanel.tsx:808-875): chọn → prefill base_url (sửa được) + dropdown model từ presets.
  - **Dropdown "Chiều vector": options lấy từ `dimensions` của model đang chọn** (thay DIMENSION_OPTIONS cứng); đổi model → options đổi theo; giá trị hiện tại ngoài danh sách vẫn hiển thị (giữ memo pattern dòng 122-128) + luôn có "Khác…".
  - **Checkbox "Dùng Batch API (−50%)"** — chỉ render khi provider được chọn `supports_batch`; unchecked mặc định.
  - Ollama → api_key optional ("Không cần cho Ollama"). Test connection gửi kèm provider.
- **FileDrawer**: status "batching" → nhãn "Chờ batch (−50%)" + icon lucide; hiện chunks_done/total khi job báo counts.
- `types.ts`/`client.ts`: `FileEntry.status` + `"batching"`; type ProviderSpec; payload `provider` + `use_batch`.
